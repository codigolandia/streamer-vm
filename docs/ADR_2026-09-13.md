# streamer-vm — Architectural Decision Record (ADR)

**Título:** Reformulação do Ciclo de Vida de Discos, Gerenciamento de Mídias, UX da CLI e Internacionalização (i18n)  
**Data:** 2026-09-13  
**Status:** Aprovado e Implementado  
**Contexto:** Evolução do design inicial (`docs/DESIGN.md`) para suporte a instalação real de SO, consolidação de Golden Image, usabilidade por fluxo e suporte bilíngue (EN/PT).

---

## 1. Contexto e Motivação

No design original (`docs/DESIGN.md`), o comando `create` criava imediatamente um disco base vazio e um overlay COW (`*-overlay.qcow2`) sobre ele. Ao inicializar a VM para instalação do sistema operacional convidado, todas as gravações eram direcionadas para o overlay, mantendo o disco base eternamente vazio.

Isso causava duas limitações críticas no fluxo operacional:
1. **Perda total do sistema com `reset`:** Executar `streamer-vm reset` destruía o overlay e recriava um overlay limpo sobre o disco base vazio, apagando o sistema operacional recém-instalado.
2. **Loop de Boot no Live CD:** O caminho da imagem ISO permanecia salvo permanentemente no `vm.json` com `bootindex=0`. Não havia mecanismo para desanexar a ISO após a instalação, forçando o QEMU a reiniciar sempre no instalador live.
3. **Falta de visibilidade do fluxo na CLI:** A saída de `--help` exibia os comandos em lista alfabética simples, sem orientar o usuário sobre a ordem correta das etapas (init → create → install → commit → use/reset).
4. **Ausência de Internacionalização:** O código misturava descrições em inglês com documentação em português sem um mecanismo padronizado de localização.

---

## 2. Decisões Arquiteturais

### 2.1 Separação de Fases: Instalação Direta na Base vs Execução em Overlay

**Decisão:** Eliminar a criação automática do overlay no comando `create`. A máquina virtual passa a operar em duas fases bem definidas:

```
                  Fase 1: Setup & Instalação
  [create] ──► [start (grava direto na base)] ──► [stop]
                                                    │
                                                    ▼ [commit]
                  Fase 2: Produção & Streaming      │
  [reset] ◄── [start (grava no overlay COW)] ◄──────┘
```

1. **Fase 1 (Setup Inicial):**
   - O `create` cria apenas o disco base `disks/<name>.qcow2`.
   - O QEMU monta diretamente o disco base caso o arquivo de overlay não exista.
   - A instalação do SO grava diretamente no disco base, aproveitando a máxima velocidade de I/O sem a sobrecarga de camadas COW intermediárias.
2. **Transição (`commit`):**
   - No primeiro commit, o estado do disco base é "congelado" como a Golden Image e o primeiro overlay `disks/<name>-overlay.qcow2` é criado vinculado a ele.
   - Em commits posteriores (após testes ou atualizações que o usuário deseja promover), o comando executa `qemu-img commit disks/<name>-overlay.qcow2` mesclando as modificações na base e recria um overlay limpo.
3. **Fase 2 (Uso Diário e Reset):**
   - O comando `start` detecta a existência do overlay e passa a montá-lo obrigatoriamente.
   - O comando `reset` descarta o overlay atual e recria um novo a partir da Golden Image consolidada no último commit. Caso a VM ainda não tenha sido commitada, o comando bloqueia a operação informando que a VM ainda está em fase de setup.

---

### 2.2 Gerenciamento de Mídias Live e Boot UEFI

**Decisão:** Criar um comando dedicado `update` e incorporar flags utilitárias nos comandos de ciclo de vida.

1. **Comando `update`:**
   - `streamer-vm update <name> --remove-iso`: limpa o campo `iso_path` para `""` no `vm.json`.
   - `streamer-vm update <name> --iso <path>`: vincula ou substitui a imagem ISO de boot.
2. **Atalhos nos comandos de ciclo de vida:**
   - `streamer-vm commit <name> --remove-iso`: consolida a imagem base e remove a mídia de instalação em uma única operação.
   - `streamer-vm start <name> --remove-iso`: remove a mídia live caso o usuário deseje iniciar diretamente sem o instalador.
3. **Comportamento no QEMU (`BuildQEMUArgs`):**
   - Se `iso_path` estiver vazio, o drive virtual de CD-ROM (`scsi-cd`) é completamente omitido dos argumentos do QEMU, permitindo que a UEFI execute o boot direto pelo disco virtual (`scsi-hd,bootindex=1`).

---

### 2.3 Preservação de NVRAM UEFI (`ovf-vars.base.fd`)

**Decisão:** Persistir um snapshot das variáveis NVRAM UEFI no momento do commit.

- **Problema:** Durante a instalação do Linux, o `efibootmgr` grava na NVRAM UEFI (`ovf-vars.fd`) as entradas de boot (como o apontamento para o GRUB EFI). Se o arquivo de variáveis for corrompido ou descartado em um reset de disco, a firmware UEFI pode não localizar o bootloader instalado.
- **Solução:**
  - Durante o `streamer-vm commit`, copia-se `configs/<name>/ovf-vars.fd` para `configs/<name>/ovf-vars.base.fd`.
  - Durante o `streamer-vm reset`, além de recriar o overlay de disco, restaura-se `ovf-vars.base.fd` de volta para `ovf-vars.fd`, garantindo paridade absoluta entre a tabela de partição do disco e a NVRAM de inicialização.

---

### 2.4 Interface CLI Orientada a Ciclo de Vida (Workflow-Driven Help)

**Decisão:** Reformular o comando de ajuda (`PrintHelp()`) para exibir o fluxo recomendado e agrupar comandos por responsabilidade.

- Ao executar `./streamer-vm` sem argumentos ou com `--help` / `-h`, a saída apresenta:
  1. Descrição geral da ferramenta.
  2. **Fluxo Recomendado passo a passo (1 a 7)** explicando a sequência correta de execução.
  3. Comandos agrupados por etapa:
     - `1. Setup & Installation (Base Image)`: `init`, `create`, `update`, `commit`
     - `2. Daily Execution & Streaming (Overlay Mode)`: `start`, `stop`, `status`, `spice-url`
     - `3. Maintenance & Recovery`: `reset`, `list`, `delete`
  4. Flags globais disponíveis (`--help`, `--lang`).

---

### 2.5 Internacionalização (i18n) em Pure Go (Standard Library)

**Decisão:** Implementar sistema de tradução nativo sem dependências externas, usando `embed.FS` e dicionários JSON.

```
internal/i18n/
├── i18n.go               # Detecção de locale, mutex e função T(key, args...)
├── i18n_test.go          # Teste de paridade estrita entre catálogos
└── locales/
    ├── en.json           # Catálogo em Inglês
    └── pt.json           # Catálogo em Português
```

1. **Princípio de Segurança:** Zero dependências externas de terceiros (prevenção contra ataques de supply chain).
2. **Prioridade de Detecção:**
   - Flag de linha de comando: `--lang=pt` ou `--lang=en`
   - Variável de ambiente do app: `STREAMER_LANG`
   - Variáveis de ambiente POSIX do host: `LC_ALL`, `LC_MESSAGES`, `LANG`
   - Fallback padrão: `en` (Inglês)
3. **Garantia de Qualidade por Teste de Paridade:**
   - O teste `TestCatalogParity` inspeciona reflexivamente os JSONs embutidos e falha a compilação de teste caso qualquer chave exista em `en.json` mas falte em `pt.json` (ou vice-versa).
4. **Documentação Bilíngue:**
   - `README.md` padronizado em **Inglês** para o ecossistema open source global.
   - `README.pt-br.md` mantido integralmente em **Português**.
   - Links mútuos de alternância inseridos no cabeçalho de ambos os documentos.

---

### 2.6 Empacotamento de Release (`.goreleaser.yaml`)

**Decisão:** Limpar os artefatos empacotados nos tarballs de distribuição final.

- Removida a diretiva `- docs/*` que distribuía documentação interna de planejamento/design para o usuário final.
- Incluído o `- README.pt-br.md` junto ao `- README.md` e `- LICENSE`.

## 3. Matriz Comparativa de Mudanças

| Aspecto | Implementação Anterior | Nova Implementação (2026-09-13) |
|---|---|---|
| **Overlay Inicial** | Criado no `create` (antes de instalar SO) | Criado apenas no primeiro `commit` |
| **Escrita na Instalação** | No overlay COW | Diretamente no disco base `*.qcow2` |
| **Comando `commit`** | Inexistente | Mescla overlay na base (`qemu-img commit`) e ativa overlay |
| **Comando `reset`** | Apagava a instalação do SO | Retorna ao estado do último `commit` |
| **NVRAM UEFI** | Não versionada pós-instalação | Backup automático (`ovf-vars.base.fd`) restaurado no `reset` |
| **Remoção de ISO** | Não suportada (apenas editando JSON) | Suportada via `update --remove-iso`, `commit --remove-iso` e `start --remove-iso` |
| **Ordem de Boot** | Sempre travada na ISO se existente | Dinâmica (omite CD-ROM se ISO for vazia) |
| **CLI Help** | Lista alfabética plana | Orientada ao fluxo de ciclo de vida (7 etapas e grupos lógicos) |
| **Localização** | Monolíngue / Mista | Bilíngue (EN/PT) com detecção automática e flag `--lang` |
| **Release Tarball** | Incluía `docs/*` interno | Apenas binário, `README.md`, `README.pt-br.md` e `LICENSE` |

## 4. Testes e Validação

Todas as alterações foram cobertas por testes automatizados nativos do Go (`go test -v ./...`):
- **E2E CLI (`cmd/cmd_test.go`):** Validação de `init` → `create` (sem overlay) → `update` (attach/remove ISO) → `reset` (bloqueio pré-commit) → `commit` (inicial e subsequente) → `reset` (restauração com sucesso) → `delete`.
- **Disco e Imagens (`vm/disk_test.go`):** Teste de ciclo de vida de `CreateBaseDisk`, `CreateOverlayDisk`, `CommitOverlayDisk` e `RemoveOverlayDisk`.
- **Boot e QEMU (`vm/qemu_test.go`):** Validação de seleção dinâmica entre overlay e base disk e geração de argumentos.
- **Paridade i18n (`internal/i18n/i18n_test.go`):** Validação de resolução de idiomas e consistência de 100% das chaves entre `en.json` e `pt.json`.
